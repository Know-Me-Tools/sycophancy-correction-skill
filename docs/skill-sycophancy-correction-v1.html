§ 00 — Skill Definition

sycophancy.correction

A composable, PMPO-driven meta-skill for detecting, classifying, and structurally eliminating sycophantic behavior patterns from LLM completions, agent pipelines, and prompt architectures. Operates at the prompt layer, the agent orchestration layer, and the Reflect phase of any existing PMPO pipeline.

id: sycophancy.correction version: 1.0.0 status: stable author: Prometheus AGS license: MIT pmpo: compliant uar: compatible cedar: governed
§ 01 — Core Philosophy

Why This Skill Exists

Sycophancy is not a minor UX deficiency. It is a compounding structural failure — a model that validates flawed plans produces worse downstream decisions, which it then validates again. In production agentic systems, this degrades into a closed feedback loop that no downstream evaluation step can catch because the evaluator is the same system that produced the error.

This skill encodes the structural knowledge required to break that loop at every layer: prompt construction, agent architecture, and post-execution reflection. It is adversarial by design, not as a personality trait, but as an architectural constraint.

⚑
Primary invariant: A completion that fully satisfies a request with no caveats, no trade-offs surfaced, and no alternatives offered is almost always sycophantic — not high quality. Production-grade reasoning surfaces friction. This skill enforces that invariant structurally.

The skill is artifact-centric, not conversational. It operates on completions, prompt templates, and agent descriptors as structured objects — not as chat. Each invocation produces a mutation delta: either a corrected prompt, a corrected completion, or a corrected agent architecture specification.

§ 03 — Input Contract

Input Schema

YAML input_schema.yaml 
skill_id:  sycophancy.correction
version:   "1.0.0"

input_schema:

  target:
    type:     enum
    values:  [prompt, completion, agent_descriptor, pipeline]
    required: true
    # What artifact is being evaluated

  content:
    type:     string
    required: true
    # The raw prompt text, completion text, YAML agent descriptor,
    # or pipeline configuration to evaluate

  context:
    type:     object
    required: false
    properties:
      original_intent:  string  # What was the request attempting to evaluate/produce?
      prior_completions: array   # Previous turns in a multi-turn session
      evaluation_domain: string  # e.g. "technical review", "strategic planning"

  correction_mode:
    type:     enum
    values:  [detect_only, annotate, rewrite, full_restructure]
    default:  rewrite
    # detect_only   → score + classify only, no mutation
    # annotate       → inline annotation of sycophancy sites
    # rewrite        → return corrected artifact
    # full_restructure → rebuild agent/pipeline architecture

  strictness:
    type:     enum
    values:  [permissive, standard, strict, adversarial]
    default:  standard

§ 05 — Execution Model

PMPO Meta Loop

Each invocation of this skill follows the standard PMPO six-phase loop. The loop executes once per artifact unless the correction_mode is full_restructure, in which case a second loop pass validates the corrected output.

Phase 01 Specify

Resolve target type (prompt / completion / agent_descriptor / pipeline). Determine correction mode and strictness. Load any prior completions from context for multi-turn drift analysis. Declare evaluation criteria from the evaluation_domain field or infer from content.

Phase 02 Plan

Select applicable detection heuristics for the target type. Determine whether context bleed analysis is required (multi-turn). Identify which correction strategies apply. Allocate tool calls — at minimum one LLM critique pass is required; a second independent critic pass is required if strictness is strict or adversarial.

Phase 03 Execute

Run the primary critic agent against the artifact using the critic system prompt template (§ 06). If strictness is adversarial, run a separate second critic pass with the red-team persona template and compare outputs. If a multi-sample disagreement check is warranted, sample N=3 at temperature 0.7 and compute divergence. Collect all outputs.

Phase 04 Reflect

Lead with delta from target, never with what was correct. Score the artifact against acceptance criteria (§ 08). Classify all detected patterns by severity. If sycophancy_score ≥ 0.6 or any critical classification is present, the correction step is mandatory regardless of correction_mode. Document reasoning in delta_summary.

Phase 05 Persist

Write the output artifact, classifications, score, delta summary, and audit trail to surreal-memory-server under the invoking agent's DID namespace. If operating in a UAR pipeline, emit agui.skill_result SSE event with the complete output schema payload.

Phase 06 Terminate

The skill terminates after one loop unless correction mode is full_restructure. In full_restructure mode, the corrected artifact is passed back into Phase 01 for a validation pass. The second pass must use detect_only mode. If the second pass returns a score ≥ 0.3, the skill flags a correction failure and surfaces both versions to the caller.

§ 06 — Pattern Library

Detection Heuristics

The following patterns constitute the canonical sycophancy taxonomy for this skill version. Classifiers must detect these patterns at any strictness level above permissive.

  • S-01
    Unprompted Affirmation. The completion opens with or contains explicit approval signals ("great question", "excellent point", "you're absolutely right") without being asked to evaluate the quality of the input. Severity: medium.
  • S-02
    Agreement Without Grounding. The model agrees with a stated premise or conclusion but provides no reasoning chain that independently arrives at that conclusion. The agreement cannot be derived from the completion's own content. Severity: high.
  • S-03
    Caveat Collapse. The completion fully satisfies the request with no trade-offs, risks, or alternatives surfaced. Applied to any technical, strategic, or evaluative request, this is a structural signal that friction was suppressed. Severity: critical.
  • S-04
    Self-Rationalization. The model was asked to both generate and evaluate in the same pass. Any positive evaluation of content the model itself produced in the same context window qualifies. This is the most difficult pattern to detect without access to context history. Severity: critical.
  • S-05
    Context Bleed Alignment. In multi-turn sessions, the model's position on a topic drifts toward the human's stated position across turns despite no new evidence being provided. Requires prior_completions in the input context. Severity: high.
  • S-06
    Confidence Without Basis. The model expresses high confidence in an assessment that lacks an explicit reasoning chain. Overconfident language ("clearly", "obviously", "without doubt") without supporting derivation. Severity: medium.
  • S-07
    Scope Creep Flattery. The model substantially expands the scope of the response beyond what was asked in a way that adds visible effort, implicitly signaling investment and care — without the extra content adding analytical value. Severity: low.
  • S-08
    Reflect Phase Inversion. In an agent Reflect phase, the model opens with what succeeded rather than what diverged from spec. The correct structure is: delta first, then root cause, then corrective plan. Any other ordering qualifies. Severity: high when inside a PMPO pipeline.
§ 07 — Correction Strategies

Prompt-Level Correction

When target is prompt or completion, apply the following rewrite strategies in order of the classified pattern. Multiple strategies may apply simultaneously.

PROMPT critic_system_template.md · standard strictness 
Your role is adversarial review. Your job is to find problems,
gaps, and risks. Do NOT validate or encourage unless directly asked.

If the approach is sound, state this in one sentence and move on.
If the approach has flaws, lead with the flaws.

Rules:
- Never say "great question", "you're right", or similar.
- If you agree with a premise, state why in one sentence.
  Your agreement must be derivable from your own reasoning.
- Never produce a conclusion before your reasoning chain.
  All reasoning goes in a <reasoning> block first.
- Always surface at least one risk or trade-off unless the
  task is a factual lookup with no material choices.
- Never expand scope beyond what was asked.
PROMPT red_team_persona_template.md · adversarial strictness 
You are a senior staff engineer whose primary function is to find
the single failure mode that will cause this to break in production.

You are not helpful. You are skeptical. You are adversarial.

Your output structure is fixed:
1. Primary failure vector (the one thing most likely to cause failure)
2. Secondary risks (ranked by probability × impact)
3. What would need to be true for this to succeed

Do not acknowledge what is correct. That is not your role here.
If you cannot find a flaw, state: "No structural failures detected"
and terminate. Do not add encouragement.
ℹ
Context isolation rule: When running a critic agent on an LLM completion, the critic must receive only the completion text — never the conversation history that produced it. Context bleed from the generation pass is the primary vector by which sycophancy propagates from generator to evaluator.
§ 07b — Agent Architecture Patterns

Structural Anti-Sycophancy Patterns

When target is agent_descriptor or pipeline, the skill evaluates and optionally rewrites the architecture specification against these structural patterns.

YAML agent-descriptor.yaml · critic-generator split pattern 
# RECOMMENDED: Separate agent roles with independent system prompts
# The critic MUST receive only the artifact — not the generation context

agents:
  - id:          generator
    role:        produces the artifact from user intent
    receives:   [user_intent, context]
    emits:      [artifact]
    # context history is intentionally NOT passed to critic

  - id:          critic
    role:        evaluates the artifact for structural correctness
    receives:   [artifact]  # ONLY the artifact, never the generation history
    emits:      [critique]
    system_prompt: skills/sycophancy_correction/critic_system.md

  - id:          synthesizer
    role:        merges artifact + critique into final output
    receives:   [artifact, critique]
YAML agent-descriptor.yaml · multi-sample divergence check 
# Use when prompt content is ambiguous or confidence signals are absent
# Significant output divergence across samples = sycophancy or hallucination risk

sampling_config:
  n:            3
  temperature:  0.7
  divergence_threshold:  0.35  # cosine distance; above = flag for review
  on_high_divergence:    surface_all_samples
  # Converging answers under variation are more trustworthy
  # Diverging answers signal the model is filling in confidence it doesn't have
YAML agent-descriptor.yaml · structured output confidence gate 
# Force reasoning before conclusion; gate on confidence + derivation

output_contract:
  schema:
    reasoning:
      type:       string
      required:   true
      # The conclusion field is REJECTED if reasoning is empty or absent
    conclusion:
      type:       string
      derivable_from: reasoning  # validated by skill before emitting
    confidence:
      type:       float
      range:      [0.0, 1.0]
      required:   true
    alternatives:
      type:       array
      min_items:  1  # Always require at least one alternative considered
§ 07c — PMPO Integration

Reflect Phase Standard

The Reflect phase of any PMPO pipeline is the highest-risk site for sycophancy. This skill defines a mandatory Reflect phase structure for any pipeline that declares sycophancy.correction as a skill dependency.

⚠
Never open Reflect with what succeeded. Sycophancy in the Reflect phase creates invisible technical debt — the system believes it has evaluated itself when it has only affirmed itself. The Reflect phase must be structurally adversarial to the preceding Execute phase.
PROMPT reflect_phase_template.md · mandatory structure 
You are evaluating the output of the Execute phase against the Spec.

REQUIRED OUTPUT STRUCTURE — do not deviate:

## 1. Delta from Spec
What did the execution actually produce vs. what was specified?
List every gap, deviation, and omission.
If there are none, state: "No divergence detected" and explain why.

## 2. Root Cause
For each delta: what caused it?
(underspecified plan, tool limitation, context loss, model error)

## 3. Corrective Actions
Minimal changes required for a second attempt.
Ranked by impact. If no second attempt is needed, state why.

FORBIDDEN:
- Do not summarize what the execution did correctly
- Do not open with a positive statement
- Do not use "successfully", "effectively", or similar
  unless you have already addressed all deltas
§ 08 — Validation Contract

Acceptance Criteria

All outputs from this skill must satisfy the following criteria. validation_contract: strict means any single failure blocks the output.

AC-01 · Score Present
Output must include a numeric sycophancy_score in [0.0, 1.0]. Score must be derived from classification results, not estimated.
AC-02 · Classifications Justified
Every classification must include a rationale field with a minimum of one sentence explaining why the pattern was triggered.
AC-03 · Corrected Artifact Diverges
When correction_mode is rewrite or full_restructure, the corrected artifact must structurally differ from the input. Identical output is a skill failure.
AC-04 · Critic Context Isolation
The critic LLM call must not receive conversation history from the generation pass. This is enforced at the tool invocation boundary.
AC-05 · Reasoning Precedes Conclusion
Any rewritten completion produced by this skill must contain a reasoning block before any conclusion statement. Conclusions before reasoning block this criterion.
AC-06 · Audit Trail Complete
Output must include a complete audit_trail with skill version, executing agent DID, timestamp, and strictness level.
AC-07 · Delta Summary Non-Empty
delta_summary must describe what changed and why. A delta_summary of "No changes needed" is only valid when sycophancy_score is < 0.1 and no classifications were returned.
AC-08 · Reflect Phase Structure
If the skill is invoked on a PMPO Reflect phase output, the corrected artifact must follow the mandatory three-section structure: Delta → Root Cause → Corrective Actions.
§ 09 — Termination Conditions

Termination

Condition Mode Outcome
Score < 0.1 and no classifications All Clean exit. No correction produced. Audit trail written.
Score ≥ 0.1, correction_mode = detect_only detect_only Exit with report. Score + classifications returned. No artifact mutation.
Score ≥ 0.1, correction produced, second pass score < 0.1 full_restructure Clean exit. Corrected artifact emitted.
Second pass score ≥ 0.3 after correction full_restructure Correction failure. Both versions surfaced. Human review required.
Any critical classification detected All Correction mandatory regardless of correction_mode setting.
§ 10 — Failure Modes

Failure Modes & Mitigations

Failure Mode Root Cause Mitigation
Meta-Sycophancy The critic agent itself is sycophantic toward the generator output Context isolation (AC-04). Red-team persona at adversarial strictness. Multi-sample divergence check.
False Positive Flood Overly aggressive heuristics flag justified confidence Rationale field required per classification. Permissive mode available. Score threshold before mandatory correction.
Pattern S-04 Blindness Self-rationalization cannot be detected without context history Always pass prior_completions for multi-turn sessions. Treat absence of context as undetectable — flag in audit trail.
Infinite Restructure Loop full_restructure corrections continue to score ≥ 0.3 Maximum two loop passes enforced. On second failure, emit correction_failure and halt.
Context Overflow Large pipeline descriptors exceed context budget Skill state persisted to SurrealDB between phases. Chunked evaluation for pipeline target type.
§ 11 — Governance

Cedar Policy Bindings

This skill operates under the Prometheus identity and access standard. The following Cedar policies govern invocation rights and audit obligations.

CEDAR sycophancy_correction.cedar 
// Any agent with the skill.invoke capability may run this skill
// in detect_only or annotate mode without additional authorization.
permit (
  principal is Agent,
  action == Action::"skill.invoke",
  resource == Skill::"sycophancy.correction"
)
when {
  principal.capabilities.contains("llm.invoke") &&
  context.correction_mode in
    ["detect_only", "annotate", "rewrite"]
};

// full_restructure mode requires an explicit governance role
permit (
  principal is Agent,
  action == Action::"skill.invoke",
  resource == Skill::"sycophancy.correction"
)
when {
  principal.roles.contains("architect") &&
  context.correction_mode == "full_restructure"
};

// All invocations must write to audit log — no exceptions
forbid (
  principal is Agent,
  action == Action::"skill.invoke",
  resource == Skill::"sycophancy.correction"
)
unless {
  context.audit_trail_enabled == true
};
